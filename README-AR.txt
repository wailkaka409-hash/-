مشروع MAARED — معرض الرسمات الأحمر والأسود
============================================

ماذا يحتوي المشروع؟
- index.html: الصفحة الرئيسية.
- styles.css: التصميم الأحمر والأسود المتجاوب.
- app.js: البحث، الاسم المستعار، عرض الرسمات.
- photos.json: قائمة الرسمات التي تظهر في المعرض.
- images/: ضع هنا صور الرسمات العامة.
- admin.html / admin.js / admin.css: لوحة الإدارة.
- netlify/functions/api.mjs: خادم API للتحقق من المدير وحفظ الأعضاء والبنرات.
- supabase-schema.sql: إنشاء جدول الأعضاء في قاعدة البيانات.
- netlify.toml: إعداد Netlify.

مهم جدًا: المشروع لا يصبح نظامًا حيًا بمجرد رفع الملفات. يجب إعداد Supabase وNetlify كما يلي.

الجزء الأول — إنشاء قاعدة البيانات
-----------------------------------
1) افتح https://supabase.com/ من المتصفح وسجّل الدخول/أنشئ مشروعًا جديدًا.
2) أنشئ مشروعًا جديدًا. احتفظ بكلمة مرور قاعدة البيانات في مكان آمن ولا ترسلها لأحد.
3) داخل المشروع افتح SQL Editor ثم New query.
4) افتح ملف supabase-schema.sql من هذه الحزمة، وانسخ كل محتواه والصقه في SQL Editor ثم اضغط Run.
5) افتح Project Settings > API (قد تظهر باسم Data API / API Keys حسب واجهة Supabase).
6) انسخ Project URL، واحتفظ به.
7) انسخ service_role / secret key. هذا سرّ إداري بالغ الحساسية: لا تضعه في app.js أو index.html ولا ترسله لأي شخص. ضعه فقط في Environment Variables على Netlify.

الجزء الثاني — رفع المشروع بطريقة تدعم الدوال الخلفية
-------------------------------------------------------
Netlify Drop العادي مناسب للملفات الثابتة، لكنه ليس طريقة موثوقة لنشر Netlify Functions من ZIP. استخدم مستودع GitHub متصلًا بـ Netlify:
1) أنشئ مستودعًا جديدًا على https://github.com/ من المتصفح.
2) ارفع ملفات المشروع إلى المستودع مع الحفاظ على بنية المجلدات، خصوصًا netlify/functions/api.mjs.
3) في Netlify، اختر Add new site / Import an existing project ثم GitHub، واختر المستودع.
4) اجعل Publish directory = . (نقطة) واترك Netlify يقرأ netlify.toml. انشر الموقع.
5) بعد نجاح النشر، افتح Site configuration > Environment variables (أو Build & deploy > Environment حسب الواجهة) وأضف المتغيرات التالية:
   SUPABASE_URL = Project URL من Supabase
   SUPABASE_SERVICE_ROLE_KEY = مفتاح الخدمة السري من Supabase
   ADMIN_PASSWORD = كلمة مرور إدارة قوية وفريدة لا تستخدمها في أي مكان آخر
   SITE_ORIGIN = رابط موقعك الكامل، مثل https://your-site.netlify.app
6) أعد تشغيل النشر / Trigger deploy حتى تتعرف الدوال على المتغيرات.

لا تكتب كلمة مرور الإدارة في ملفات المشروع أو داخل HTML. كلمة المرور لا تُحفظ في قاعدة البيانات؛ الدالة تقارنها مع متغير البيئة.

الجزء الثالث — إضافة الرسمات
-----------------------------
1) ضع الصور العامة داخل مجلد images.
2) افتح photos.json وعدّل القائمة، مثال:
[
  {
    "title": "رسمتي الأولى",
    "description": "وصف مختصر للرسم",
    "artist": "اسم الفنان",
    "image": "/images/drawing01.png",
    "download": "/images/drawing01.png",
    "date": "2026-10-17"
  }
]
3) أضف عنصرًا لكل رسمة. يجب أن يكون مسار الصورة واسمها صحيحين.
4) ارفع التعديلات إلى GitHub، وسيعيد Netlify النشر عند تفعيل النشر التلقائي.

الجزء الرابع — الاستخدام
-------------------------
- افتح رابط الموقع؛ اكتب اسمًا مستعارًا.
- سيُنشأ ملف عضو مجهول مرتبط برمز عشوائي محفوظ في متصفح ذلك الجهاز.
- افتح /admin.html وأدخل ADMIN_PASSWORD.
- اختر بنرًا للعضو واضغط حفظ البنر.
- البنرات: basic (عادي)، team-red (التيم الأساسي)، team-elite (النخبة)، team-gold (مميز).

حدود مهمة للخصوصية والهوية
--------------------------
- الاسم المستعار وحده لا يثبت هوية الشخص. لا تستخدم النظام للتحقق من الهوية الواقعية.
- رمز العضو يُحفظ في localStorage على نفس المتصفح والجهاز؛ مسح بيانات المتصفح أو تبديل الجهاز قد يفقد الوصول إلى الملف القديم.
- يستطيع الزائر تغيير اسمه أو إنشاء ملف جديد، وقد يقلّد اسم شخص آخر. لا تمنح بنرات خاصة بناءً على الاسم وحده إذا كان الانتحال مهمًا.
- لوحة الإدارة محمية بكلمة مرور على الخادم، لكن هذا نموذج بداية. قبل الاستخدام العام الكبير، أضف حماية من كثرة الطلبات ومراجعة أمنية.
- كل ما يوضع في images ويظهر في المعرض متاح للعامة ويمكن تنزيله. لا تضع صورًا خاصة أو أصلية سرية هناك.
- لا تضع SUPABASE_SERVICE_ROLE_KEY في أي ملف عام. إذا انكشف المفتاح، ألغِه وولّد بديلًا فورًا.
